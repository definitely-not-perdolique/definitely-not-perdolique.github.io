Программирование: тестирование и дебагинг. Для тестирования нужно разгруппировать юзер инпут, построить тесты в которых содержатся по одному инпуту из каждой группы и запустить тесты.
Способы построения тестов: black-box testing и glass-box testing.
black-box - просто вызывать тестируюмую функцию передавая ей разные значения. Не зависит от имплементации.
glass-box - ставить if-ы в самом коде. При тесте закидывать значения: минимальные, максимальные и типичные.
Рул оф самб при гласс-бокс тестинге:
- For each for loop, have tests where:
+ Loop is not entered
+ Body of loop executed exactly once
+ Body of loop executed more than once
- For each while loop
+ Same cases as for loops
- For recursive functions, test with no recursive calls, once recursive call, and more than one recursive call

Пусть вспомогательная функция выглядит как void internal_mergesort(vector<T>& a, vector<T>& b, bool inplace), в примере это _msort. Предполагается a.size() == b.size().
Функция сортирует массив A, помещая результат в B, если не выставлена inplace, или в сам A, используя B как временный буфер, если inplace выставлена.
Тривиальный случай — массив длины 1, иначе, когда она рекурсивно вызывает себя, массивы меняются ролями. Рассмотрим оба сценария.

inplace == true:
Половинки A сортируются с записью результата в B вызовом самой себя с inplace == false.
Затем отсортированные половинки объединяются назад в A.

inplace == false:
Половинки A сортируются с записью результата снова в A рекурсивным вызовом с inplace == true, затем объединяются в B.
