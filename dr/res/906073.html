Кал говна, как я и думал. Ботохуета обоссала:

Tea-lang (исследовательский язык программирования, компилируемый в PHP, либо одноименные DSL для статистики и скриптинга) не подходит для полноценной замены PHP по нескольким фундаментальным причинам.
В то время как PHP остается фундаментом мирового веба, контролируя около 75% всех сайтов, Tea-lang является либо надстройкой над ним, либо узконишевым инструментом.

1. Зависимость от самого PHP (Парадокс компиляции)

Официальный синтаксический проект Tea-lang (tealang/tea) по сути не является самостоятельной средой выполнения для веба. Он компилируется в PHP-код и требует установленного PHP 8.1+ на сервере для своей работы. Нельзя «заменить» PHP языком, который физически зависит от интерпретатора PHP для выполнения своих же программ.

2. Отсутствие экосистемы и инфраструктуры

У PHP за десятилетия сформировалась гигантская экосистема, которой у Tea-lang нет:
• Фреймворки: PHP обладает мощнейшими готовыми экосистемами вроде Laravel и Symfony. Написание бэкенда на Tea-lang потребует создания всей архитектуры (роутинг, ORM, валидация, безопасность) с нуля вручную.
• CMS: Индустрия держится на PHP-системах автоматизации контента (WordPress, Magento, WooCommerce). Tea-lang не предлагает альтернативных платформ для бизнеса.

3. Проблема развертывания (Хостинг)

PHP поддерживается «из коробки» абсолютно любым, даже самым дешевым shared-хостингом в мире. Для запуска приложений на Tea-lang потребуется настраивать кастомные цепочки сборки (build pipelines), что убивает главное преимущество PHP — мгновенный запуск по принципу «загрузил файл .php по FTP — и всё работает».

4. Критическая нехватка кадров и документации

На рынке труда нет вакансий и готовых специалистов по Tea-lang. Поиск ответов на сложные архитектурные вопросы или баги компилятора в StackOverflow сведется к нулю, в то время как по PHP доступна тонна документации, ответов и готовых библиотек под любую бизнес-задачу.

5. Концептуальное различие (Другие версии Tea)

Если под «Tea-lang» подразумеваются другие одноименные проекты (например, Tea для JVM или Tea-lang для автоматизации статистического анализа на Python), то они изначально создавались для других задач (Data Science, enterprise-скриптинг в Java) и вообще не имеют встроенных инструментов для веб-разработки, обработки HTTP-запросов, сессий и вывода HTML-страниц.
